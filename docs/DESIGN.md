## 0. 一句话方案

以 **「自托管后端 + 一份代码跑全平台」** 为核心：客户端采用 **Vue 3 单代码库 + Wails v3（Go：桌面/移动/serve 模式）+ Web** 的形态（用户 2026-11-02 决策，见 docs/ADR-002-客户端落地-Vue与Wails.md），渲染层基于 **foliate-js**（MIT；但上游无正式 release、已约 6 个月未更新，须自持 fork 固定 commit）；后端自建 **PostgreSQL + 对象存储 + 同步服务 + AI 网关**，实现多用户、离线优先的阅读进度/标注同步，并通过**可插拔书源插件**与**实体（人名/术语）归一化**形成对 Readest 的差异化。

## 1. 项目目标与范围

### 1.1 目标（本期）
1. **全平台阅读**：Web、Windows/macOS/Linux 桌面、iOS/iPadOS、Android，同一账号、同一书库。
2. **多格式**：EPUB2/3、TXT、PDF、MOBI/AZW3（KF8）、FB2、CBZ、HTML、Markdown（分级支持，见 4.2）。
3. **自托管后端**：账号体系、书库、文件存储、进度与标注同步，部署在自有服务器上。
4. **离线优先**：断网可读、可标注，联网后自动合并；冲突可见、可解释。
5. **书源系统**：通用的「书源插件」框架 + 内置合法公开书源；Z-Library 以**风险隔离**方式处理（见 4.5 与 docs/OPEN-QUESTIONS.md 的 Q5）。
6. **LLM 高级功能**：划词/整段/整章翻译、双语对照、**人物与术语译名归一化**、章节摘要、书籍问答。
7. **多用户**：注册/登录/找回密码、配额管理、管理后台、数据隔离与审计。

### 1.2 明确不做（本期）
- 不做电子书商城、不做付费内容分发、不做 DRM（LCP/Adobe DRM）破解或支持。
- 不做社交社区（书评、关注、动态）——留接口，不做界面。
- 不做 iOS/Android 应用商店上架**带 Z-Library 的版本**（合规结论见调研文档；这是硬约束，不是偏好）。
- 不做移动端原生渲染内核自研（用 WebView 方案，性能取舍见技术方案 3.6）。

### 1.3 成功标准（可度量）
| 维度 | 指标 | 目标值 |
|---|---|---|
| 阅读可用性 | 打开 10MB 级 EPUB 到首屏可读 | < 1.5s（桌面/Web），< 2.5s（中端手机） |
| 翻页/滚动 | 长文滚动帧率 | ≥ 50fps（中端手机 ≥ 40fps） |
| 同步 | 进度跨设备可见延迟（在线） | ≤ 3s（P95） |
| 同步 | 冲突导致的位置丢失 | 0（冲突只允许出现在标注文本编辑，且必须提示） |
| 格式 | EPUB 测试集渲染通过率 | ≥ 98%（W3C epub3 测试集 + 自建样本） |
| AI | 整章翻译首字返回 | < 2s，全文流式完成 ≤ 30s/千字级章节 |
| 多用户 | 单机支撑规模 | 1 千活跃用户 / 单 8C16G 节点（阶段目标） |

## 2. 竞品与差异化

### 2.1 竞品矩阵

| 产品 | 形态 | 开源/许可 | 格式 | 同步后端 | 书源/下载 | AI | 启示 |
|---|---|---|---|---|---|---|---|
| **Readest** | Tauri v2（桌面/移动）+ Next.js Web | AGPL-3.0 | EPUB/PDF/MOBI/KF8(AZW3)/FB2/CBZ/TXT/HTML/MD | 官方云（Supabase + S3/R2 + Stripe），支持 WebDAV、KOReader 同步 | OPDS/Calibre；**无 Z-Library** | DeepL/Yandex 翻译、AI 摘要（在建）、AI 对话 | **最接近的参照实现**，其架构可直接借鉴 |
| **Anx Reader** | Flutter（Android/iOS/桌面） | 开源（见仓库） | 多格式 | 自有/本地为主 | 无 | 集成多种 AI 能力（翻译、总结） | 证明「阅读器 + AI」是真实需求 |
| **KOReader** | Lua + 原生（Kindle/Kobo/Android） | AGPL-3.0 | EPUB/PDF/CBZ/DJVU 等 | kosync（轻量 JSON 协议） | 无 | 无（插件） | **同步协议事实标准**，必须兼容 |
| **Legado（开源阅读）** | Kotlin（Android 为主） | GPL-3.0 | TXT/EPUB | WebDAV 等 | **自定义书源 DSL（JSON 规则）**，生态最大 | 部分 | 书源 DSL 是成熟范式；同时是**最大法律风险案例**，见 11 |
| **calibre-web / Kavita / Komga** | Web（Python/Kotlin） | GPL-3.0 | 以书库管理为主 | 本地 | OPDS | 无 | 自托管书库后端的功能基线（用户、书架、OPDS、权限） |
| 微信读书 / Apple Books / Kindle | 闭源 | 闭源 | 各自生态 | 厂商云 | 商城 | 有（厂商） | 体验标杆：进度语义、划线交互、竖排/横竖屏适配 |

> 证据：Readest 功能与格式列表见 [Readest README](https://github.com/readest/readest)；其系统架构见 [architecture.md](https://github.com/readest/readest/blob/main/apps/readest-app/docs/architecture.md)；KOReader 同步服务见 [koreader-sync-server](https://github.com/koreader/koreader-sync-server)；Legado 书源见 [gedoor/legado](https://github.com/gedoor/legado)；Anx Reader 见 [Anxcye/anx-reader](https://github.com/Anxcye/anx-reader)。

### 2.2 Readest 事实基线（已核实）

| 项目 | 事实 |
|---|---|
| 定位 | Foliate 的现代重写，跨 macOS/Windows/Linux/Android/iOS/Web |
| 前端 | Next.js 16 + React 19，Monorepo（pnpm），apps/readest-app |
| 客户端壳 | **Tauri v2**（桌面 + Tauri mobile）；Web 走 Next.js/OpenNext on Cloudflare Workers |
| 渲染引擎 | foliate-js（仓库内 packages/foliate-js） |
| 本地数据 | 浏览器/WebView 内 **Turso/libSQL WASM 副本库**（依赖 SharedArrayBuffer，因此需要 COOP/COEP 响应头） |
| 状态管理 | Zustand 多 store（libraryStore/bookDataStore/readerStore/notebookStore/settingsStore 等） |
| 服务抽象 | src/services/environment.ts + webAppService/nativeAppService/nodeAppService，同一套业务代码跑在 invoke() 与 fetch() 两侧 |
| 后端 | Next.js API routes + Supabase（auth + Postgres）+ S3/R2 + Stripe + 应用内购 |
| 可部署性 | 存在 docker/ 与 /runtime-config.js 运行时注入机制，**同一镜像可通过运行时配置切换 Supabase 项目 / S3 端点 / 配额** |
| 阅读器规模 | app/reader 约 80 个组件、30 个 hooks（渲染、标注、脚注、笔记本、平行阅读、RSVP、AI 对话、翻译、搜索、TTS） |
| 许可 | **AGPL-3.0**（关键：若我们参考/复制其代码，本项目也须以 AGPL 开源） |

### 2.3 我们的差异化（相对 Readest）
1. **后端完全自托管、可脱离任何商业 SaaS**（Readest 强依赖 Supabase/Stripe/IAP）。
2. **真正的多用户运营能力**：配额、管理后台、审计、可选家庭共享。
3. **书源插件体系**（Readest 仅有 OPDS/Calibre 目录，无「搜索并下载」能力）。
4. **LLM 深度整合**：不止翻译，而是**全书实体档案（人名/地名/术语）归一化 + 一致性保证**，这是 Readest/Anx 都未解决的问题。
5. **中文阅读场景优化**：竖排、标点挤压、简繁转换、中文分词搜索、中文 TTS。

## 3. 用户角色与典型场景

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 读者（主用户） | 个人跨设备读书 | 进度不丢、划线同步、手机竖屏通勤读、平板横屏双栏、桌面深度阅读 |
| 重度读者/研究者 | 大量 PDF + 外文原版 | PDF 标注、双语对照、术语/人名一致、笔记导出 |
| 管理员 | 部署与运营者（你） | 用户管理、配额、存储监控、备份恢复、审计日志 |
| （可选）访客/共享成员 | 家庭或小团队 | 共享书架、只读分享链接 |

**关键场景**（验收时逐条走查）：
1. 手机竖屏地铁里读完一章 → 回家打开桌面端，位置精确续读、高亮齐全。
2. 平板横屏双栏 + 桌面双窗口平行阅读两本书。
3. 导入 300MB 扫描版 PDF，能翻页、能划词（无文本层时降级为区域标注/OCR）。
4. 搜索「三体」→ 从合法书源（或用户自配书源）下载 → 自动入库 → 抓取元数据与封面。
5. 读英文原版，划词翻译并「一键生成人名译名表」，后续章节翻译自动沿用同一译名。

~~~

│   ├── 笔记面板（Notebook）
│   ├── 翻译/术语表
│   └── AI 助手面板        摘要、问答、实体档案
├── 发现（Discover）       书源聚合搜索、OPDS、Calibre
├── 统计（Stats）          P2
└── 设置 / 账号
    ├── 阅读设置（字体/主题/布局/翻页）

    ├── AI 设置（模型、密钥、隐私开关）
    ├── 书源管理

**导航形态差异**
- 手机竖屏：底部 Tab（书库 / 发现 / 统计 / 设置）；阅读器内为浮层（点击中央唤出）。
- 手机横屏 / 平板：侧边栏（可收起）+ 阅读区；支持双栏。
- 桌面 / Web：左侧栏 + 主区域；阅读器可独立窗口/标签页；完整快捷键。

## 6. 关键界面设计要点

### 6.1 横竖屏与设备适配矩阵（硬性要求）
| 设备/姿态 | 布局 | 阅读视图 | 边栏 | 备注 |
|---|---|---|---|---|
| 手机 竖屏 | 单列 | 单栏分页（或竖向滚动） | 抽屉浮层 | 状态栏沉浸；安全区适配（刘海/挖孔） |
| 手机 横屏 | 单列（内容居中） | **双栏**（可选单栏） | 抽屉浮层 | 高度受限，优先隐藏工具栏 |
| 小屏平板 竖/横 | 单/双列 | 单栏 or 双栏 | 可收起侧栏 | |
| 大平板 横屏 | 双列 | 双栏 + 常驻侧栏 | 常驻 | 支持平行阅读 |
| 桌面/Web ≥1280px | 三区（侧栏/内容/检查器） | 单/双栏 | 常驻可折叠 | 快捷键全量 |
| 桌面 窄窗口 | 折叠侧栏 | 单栏 | 浮层 | 与平板行为一致 |

实现要点：**不依赖屏幕尺寸猜设备**，用「可用宽度 + 是否触控 + 是否窄高」三要素驱动布局；旋转时保持阅读位置（Locator），不丢锚点。

### 6.2 阅读器界面
- **三区制**：顶部（书名/进度/操作）· 主阅读区 · 底部（进度条/页码/剩余时间）。顶部与底部可自动隐藏（点击/滚动方向驱动）。
- **点击分区**：左 1/3 后退、右 1/3 前进、中间唤出工具栏（可自定义，适配左手/右手）。
- **划词浮层**：高亮（多色）、笔记、复制、翻译、查词、朗读、AI 解释，按钮顺序可配置。
- **阅读进度条**：章节刻度 + 标注密度热力（P2）。
- **脚注**：点击内联弹出，不离开当前页。
- **竖排/横排**：中文竖排（writing-mode）作为 P2，但排版层从 P0 起就按「块级流 + 可插拔排版引擎」设计，避免后期返工。

### 6.3 阅读设置项（P0 全量）
字号、字体（系统/内置/用户导入）、字重、行距、段距、首行缩进、页边距、对齐、主题与自定义配色、翻页动画（无/滑动/淡入/覆盖）、分页 or 滚动、单双栏、标点挤压、简繁转换（P2）、字号跟随系统。

### 6.4 书库
- 视图：网格（封面为主）/ 列表（元数据为主）；分组：全部/最近/未读/在读/已读/收藏/文件夹/标签。
- 多选批量：加入书架、下载、删除、编辑元数据。
- 拖拽导入（桌面/Web）、系统「打开方式」关联（桌面/移动）、分享导入（移动）。
- 空状态引导：导入第一本书 / 配置书源 / 登录以同步。

### 6.5 AI 面板（差异化主战场）
- **翻译**：划词即时翻译；整章「后台翻译 + 双语逐段对照」；翻译记忆缓存（重复内容不重复付费）。
- **实体档案（人名归一化）**：以「卡片 + 表格」呈现 原文名 / 译名 / 别名 / 身份 / 首次出现；支持手动合并同人异名、修正译名；**保存后自动同步到所有设备并注入后续翻译**。
- **摘要**：章节摘要（可折叠）、全书梗概。
- **问答**：基于当前书（或当前章节）的 RAG 问答，答案必须带原文引用与跳转。
- **隐私**：面板首启告知「正文将发送至所选模型服务商」，默认提供「本地模型」与「关闭 AI」选项；可设置「仅对本书禁用」。

## 7. 关键流程

### 7.1 导入并开始阅读
~~~
选择文件 → 前端算 SHA-256 → 命中本地/服务端已有 → 秒级入库
        ↓ 未命中
上传（分片、断点续传、后台队列） → 服务端解析元数据/封面/目录 → 入库
        ↓
书架出现 → 点击打开 → 首次打开生成定位索引（CFI/分页） → 进入阅读
~~~
异常路径：加密 EPUB/DRM → 明确提示「不支持受 DRM 保护的书」；损坏文件 → 保留原文件并提示。

### 7.2 多设备续读
~~~
设备A 阅读 → 本地写 progress(dirty=true) → 出队 → POST /sync/push
                                        ↓
服务端 changelog 追加 rev → 等待设备B 拉取
                                        ↓
设备B 前台/后台触发 GET /sync/changes?since=cursor → 应用远端进度
                                        ↓
若设备B 本地也有未推送进度：按 位置文本优先级 + 时间戳 合并，
必要时弹「检测到两个进度，采用较远位置？」
~~~

### 7.3 划词翻译与术语表
~~~
划词 → 本地缓存查（key = hash(原文+模型+提示词版本)）→ 命中直接显示
     ↓ 未命中 → 调用 AI 网关（含本书术语表）→ 流式返回 → 写入缓存与翻译记忆
用户点「生成人名译名表」→ 全书分块 NER（后台任务）→ 别名聚类 → 生成草案
     → 用户在面板中确认/编辑 → 保存为本书 EntityProfile → 同步 + 注入后续翻译
~~~

### 7.4 书源搜索与下载
~~~
输入关键词 → 并发查询「已启用的书源」（规则引擎执行）
   → 聚合去重（按 书名+作者 相似度）→ 展示来源、格式、大小、语言
   → 选择 → 下载任务（可断点续传）→ 入库 → 元数据补全（书源/Google Books/OpenLibrary）
~~~
规则引擎：JSON 声明式规则（请求模板 + CSS/XPath/正则抽取 + 分页 + 编码处理），**不执行任意脚本**（安全 + 可审计），这与 Legado 的 JS 规则不同，是刻意的安全取舍。

## 8. 交互与体验规范
- **无障碍**：键盘全导航、屏幕阅读器（VoiceOver/TalkBack/NVDA/Orca）、对比度 ≥ 4.5:1、Web 端 200% 缩放不破版。
- **国际化**：zh-CN 为默认，i18n 框架从 P0 接入（en 同步维护）。
- **快捷键**（桌面/Web）：翻页 ←/→/Space、目录 T、搜索 Ctrl+F、主题 Ctrl+D、翻译 Ctrl+Shift+T、全屏 F11。
- **手势**（移动）：左右滑动翻页、上下滑动亮度、双指缩放字号、长按选词、边缘内滑返回。
- **性能体感**：任何耗时操作（导入/翻译/下载/转换）必须有可见进度与取消；禁止无反馈等待超过 300ms。

## 9. 同步的用户可见行为（产品视角）
- 顶部/设置中显示**同步状态**：已同步 · 2 分钟前 / 同步中… / 离线，3 项待同步 / 同步失败，点击重试。
- 冲突**必须可见**：进度冲突给「采用较远位置 / 保留本机」选择；标注文本冲突给 diff 视图。
- 用户可选择**只同步进度**（省流量）或**同步标注与设置**。
- 提供「设备管理」：查看已登录设备、最后活跃时间、远程登出。

## 11. 主要风险与依赖
| 风险 | 影响 | 应对 |
|---|---|---|
| **Z-Library / 书源的法律风险** | 极高：可能导致项目被封禁、开发者个人担责；商店下架 | 官方不分发/不托管侵权源；只做通用规则引擎；内置源仅合法公开库；商店版本禁用第三方源；详见 docs/OPEN-QUESTIONS.md 的 Q5 |
| AGPL 传染（若参考/复用 Readest 代码） | 项目须开源 | 明确选择：AGPL 开源 or 参考架构自研（见 OPEN-QUESTIONS Q4） |
| **Wails v3 移动端为 experimental**（官方明确不在稳定性承诺内） | 高：可能上不了手机 | **G1 Spike 前置 2–3 天**，失败即启动预案（移动端改 PWA / 延后 / 原生双栈） |
| **旧版 Android WebView 导致白屏**（WebView 83–99；受影响机型含 Onyx Boox / Moaan 等 e-ink 阅读器、无 Play 服务的 AOSP、部分华为机型）——**正对电子书阅读器的核心用户群** | 高 | 设 **M2 为 Go/No-Go 决策点**；预案：集成 WebView 升级/降级渲染路径，或移动端改 Readium Swift/Kotlin 原生双栈 |
| 格式兼容长尾（畸形 EPUB、扫描 PDF、MOBI 变种） | 用户体验 | 建立格式样本库 + 回归测试；明确降级策略 |
| LLM 成本与隐私 | 成本/信任 | AI 网关统一计费与缓存；默认关闭外发；支持本地模型 |
| 单机服务器容量（文件 + 备份） | 可用性 | 对象存储 + 去重 + 分级备份；明确容量与扩容路径 |
| **foliate-js 上游停滞**（无 release、约 6 个月无提交、npm 上同名包非作者发布） | 高：内核不可指望上游修 bug | 自持 fork（git submodule 固定 commit）+ 自建格式回归集；保留切换 Readium TS 的接口边界 |
| 上游（Readest）演进 | 分叉维护成本 | 若不 fork，则只借鉴架构，不跟踪上游 |
