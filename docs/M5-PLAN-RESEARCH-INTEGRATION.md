## 13. 整合调研结论（80 号：人名归一化）

调研文档：[`docs/research/80-entity-normalization.md`](research/80-entity-normalization.md)（769 行，全部断言带来源 URL）。
下面是我采纳的**修正**，以及我**不采纳**的部分。

### 13.1 采纳：把「归一化」设计成实体注册表 + 可重放修正日志（这比我的原方案好）

**我原方案（§11）的缺陷**：只说了「用户确认后回灌 glossary」，没解决**重跑会覆盖用户工作**的问题。
LLM 抽取是概率性的，同一本书重跑一次，分组可能变——用户的确认就被冲掉了。

**调研给的更好答案**：
- **不存「改后的结果」，存 append-only 的修正日志**（操作类型：merge / split / rename / alias_add / lock）；
- 自动流水线每次重跑后**重放日志**，用户工作永不丢失；
- 日志同时是**负样本**：`blocked_pairs` 记录「用户明确拆开过的对」，防止重跑又合回去。

**为什么这个更好**：把「用户意图」和「算法结果」分开了。算法可以随便升级、重跑、换模型，用户意图永远在日志里。
这是**架构层面的正确性**，不是优化。**采纳，写进 M5-3/M5-4 的验收条件。**

### 13.2 采纳：译后确定性扫描（把概率问题变成可判定问题）

**我漏掉的一环**：即使译前把术语表塞进 prompt，模型**仍可能不遵守**（概率性）。
我原方案没有任何校验——译错了也不知道。

**调研给的答案**：译后用**确定性扫描**（不花 LLM 钱）统计每个标准译名在译文里出现次数，
**出现 0 次即判定「译者忽略了术语表」→ 只重译该段**。

**为什么好**：这是纯字符串统计，零成本、可单测、结果确定。它把「术语是否一致」从「祈祷模型听话」变成「可验证的断言」。
**采纳，作为 M5-2 的验收项**：整书翻译完成后必须跑一遍扫描，输出「违规段落数」。

### 13.3 采纳：分块用 6000 token / 不重叠 / 滚动术语表，并诚实记录「分块更贵」

调研实测：分块比整书一次性**贵 1.9 倍**，买的是**断点续跑 + 增量重跑 + 避开中段遗忘**。
我认为这个交换**值得**，因为整书一次性失败要重头再来（2 元重花一次），分块失败只重跑一块。
但**必须在文档里写明这个代价**，不能让用户以为是免费的。

### 13.4 采纳：一期不上任何模型（LLM + 纯 Go 确定性层）

调研建议：一期 `OpenCC 归一 + 拼音 key + 子串包含 + 并查集`（全是纯 Go 库，零 CGO），
二期再考虑 ONNX + GLiNER，**永不引入 Python 侧车**。

**我同意，理由**：
- 一期要验证的是「这套流程能不能让译名一致」，**不是「NER 准不准」**；
- CGO 会污染整个构建链（我们刚为 Android 双 ABI 折腾过，不想再引入 CGO 风险）；
- 一期不上模型，失败模式更简单，更容易定位问题。

**Go 库选型（调研已核实许可证）**：
> 以下三个库我**逐个用 GitHub API 核实过**（2026-11-03）：许可证、语言、活跃度。

| 库 | 导入路径 | 许可证 | 实测 | 用途 |
|---|---|---|---|---|
| opencc | `github.com/longbridge/opencc` | **Apache-2.0** | 纯 Go（`language: Go`）、116★、最近推送 2024-12-10 | 繁简归一 |

### 13.5 不采纳 / 需验证

| 项 | 我的处理 |
|---|---|
| ONNX + GLiNER 二期 | **暂不承诺**。调研自己列了 U2（CGO 能否进 Wails 移动端包未验证）——这和我们刚经历的 Android 构建风险同类，**要先做 spike 再决定** |
| 归化译名（郝思嘉 vs 斯嘉丽） | **明确接受做不到**。字符串法必然失败，只能靠 LLM 或人工。UI 上要**如实告诉用户「这类需要你手动确认」**，不要假装能自动 |
| 真实书 surface form 数量 | **必须实测**（调研 U8）。它直接决定成本估算准不准，不能信论文数字 |

### 13.6 成本对齐（两份估算交叉验证）

我的估算（§8.2）：30 万字 ≈ 20 万 token（0.67 token/字）
调研的估算（官方口径）：30 万字 = 18 万 token（0.6 token/字）

**两者基本一致**（差异来自 tokenizer 口径）。调研的三阶段细账（输入 29.27 万 / 输出 4.2 万）比我粗估更细，
结论都是 **flash 低峰约 0.5 元/本**，与我的 §8.2「1~2 元」同量级（我偏保守）。**以调研的细账为准。**
